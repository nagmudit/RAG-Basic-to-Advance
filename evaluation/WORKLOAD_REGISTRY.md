# Workload and comparison registry

Metrics are comparable only when dataset/query/judgment definitions permit comparison. A larger score on a different workload is not evidence that a later engine improved. Match cutoff, eligibility, model/input contract and metric policy; timing comparisons also need matched boundaries and environment.

The structured companion [WORKLOAD_REGISTRY.json](WORKLOAD_REGISTRY.json) is the canonical identity source checked by tests. This table summarizes it. Pre-remediation result files are immutable historical observations; the registry assigns them workload identities without rewriting their metrics. Fresh experiment results and future headline tables must carry `workload_id` (or one ID per distinct fixture).

Relevant source identities, counts and slices are stored beside each JSON registry entry. Re-register any changed query/label definition; source changes require the [evidence identity review](EVIDENCE_IDENTITY.md). Do not automatically update a digest to pretend stale judgments still apply.
