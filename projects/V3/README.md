# Build Your Own RAG Engine — V3, Chapters 10–12 vector, encoder and adaptation stages

V3 spans Chapters 10–14 in the [project roadmap](../../PROJECT_ROADMAP.md). **Chapters 10–12 are implemented.** Chapter 10 supplies an [exact vector oracle](exact_vectors.py) on declared coordinates. Chapter 11 adds a frozen pretrained sentence encoder and a newly judged query probe. Chapter 12 trains a small query-side adapter with source-disjoint train/validation/test labels, keeping the base encoder and passage vectors frozen. V0's fictional source snapshot, V1's analyzer/postings, V2's BM25/qrels and the two-question answer stub remain the binding baseline.

## Artifacts and boundaries

- [Exact vector code](exact_vectors.py): numeric validation, dot/cosine/L2/L1, index-time unit vectors, scoped exhaustive scoring, full sort or bounded-heap selection, raw scores, deterministic ID ties and work counters. `allowed_scopes` is a static fixture; a caller-supplied scope is **not authentication**.
- [Behavioral tests](test_exact_vectors.py): hand geometry, plan equivalence, full eligible scan, tie order, zero/dimension/nonfinite handling, duplicate IDs and support-team isolation.
- [Paired judged experiment](experiment_ch10.py) and [checked-in record](chapter-10-experiment.json): V2 BM25 versus exact cosine on dense **binary lexical term-presence** coordinates. There are 119 fixed vocabulary dimensions; no learned encoder and no semantic claim. It reuses Chapter 9's 14 frozen queries and 168 reviewed support-team query–segment pairs. The record retains candidate IDs/raw scores, qrel ranking metrics, selected context IDs/direct coverage, the limited V0 stub status, work, raw search-only timings, versions, hashes, environment and limitations.
- [Figure 10.01 source](../../visuals/chapter-10/plot-10-01-metric-geometry.py), [SVG](../../visuals/chapter-10/figure-10-01-metric-geometry.svg) and [PNG](../../visuals/chapter-10/figure-10-01-metric-geometry.png): hand-authored geometry, exact metric ranking and explicit tie rule.
- [Chapter 11 pooling and contrastive arithmetic](contrastive_math.py): standard-library masked mean, stable in-batch row-softmax loss and false-negative contract. It explains training mechanics without updating weights.
- [New frozen qrels](judgments_ch11.json): 17 questions (8 paraphrase, 6 exact-identifier, 3 no-eligible-evidence), 12 support-team segments, 204 reviewed pairs, an explicit 0/1/2 rubric and one-author limitations. [The loader](experiment_ch11.py) rejects changed roster, snapshot, illegal labels and inconsistent no-evidence slices.
- [Pinned-model experiment](experiment_ch11.py) and [raw checked-in record](chapter-11-experiment.json): `sentence-transformers/all-MiniLM-L6-v2` revision `8b3219a92973c328a8e22fadcfa821b5dc75636a`, 384 normalized coordinates, shared query/passage `encode` path and exact cosine against V2 BM25. It stores candidate IDs/scores, context IDs/direct coverage, qrel metrics by slice, model/index versions and hashes, build costs, work, and raw search/encode/scan timings. No answer generator runs on the 17 new questions.
- [Chapter 11 behavioral/data tests](test_ch11.py) and [Figure 11.01 source](../../visuals/chapter-11/plot-11-01-encoders-and-batch.py), [SVG](../../visuals/chapter-11/figure-11-01-encoders-and-batch.svg), [PNG](../../visuals/chapter-11/figure-11-01-encoders-and-batch.png).
- [Chapter 12 split and qrels](judgments_ch12.json): train D1/D2/D4/D6, validation D3/D7, held-out test D5/D8/D9; ten authored train pairs and 15 fully judged validation/test questions over the same 12 eligible segments (180 reviewed pairs). Labels are source-disjoint, but author knowledge and related wording limit independence. Chapter 9/11 inspected cases remain retrospective regressions.
- [Chapter 12 adapter runner](experiment_ch12.py) and [checked-in record](chapter-12-experiment.json): rank-16 residual projection on normalized frozen query vectors, masked softmax over only seven train-document passages, validation-selected checkpoint, then one held-out test comparison with frozen cosine and BM25. Model/split/corpus/code hashes, raw IDs/scores, context IDs, metrics, training history and request-boundary timings are retained. [Tests](test_ch12.py) reject split/positive/negative leakage and check an identity adapter. Figures [12.01](../../visuals/chapter-12/figure-12-01-training-matrix.svg) and [12.02](../../visuals/chapter-12/figure-12-02-document-split.svg) have editable plot scripts beside them.

The vector index contains all 13 V0 indexed segments, but the `support-team` search scores only 12. Legal-only D10 is excluded **before** similarity calculations and is absent from context. Real permission checks must derive scope from a trusted identity and handle live updates. The 119-coordinate vocabulary and segment representations are built at index time from V1's analyzed title/body term presence. The query gets the same coordinate map at query time. A query with no vocabulary terms has a zero vector; the wrapper returns no candidates and records the reason because cosine is undefined there. Other cosine queries score every eligible nonzero vector, including zero-similarity items. The exact index is the oracle for its declared representation/metric, not for human relevance.

## Reproduce

From the repository root:

```powershell
python -X utf8 -m unittest discover -s projects/V3 -p 'test_*.py' -v
python -X utf8 projects/V3/experiment_ch10.py --output projects/V3/chapter-10-experiment-local.json
python -X utf8 visuals/chapter-10/plot-10-01-metric-geometry.py
python -X utf8 projects/V3/contrastive_math.py
python -X utf8 projects/V3/experiment_ch11.py --output projects/V3/chapter-11-experiment-local.json
python -X utf8 visuals/chapter-11/plot-11-01-encoders-and-batch.py
python -X utf8 projects/V3/experiment_ch12.py --output projects/V3/chapter-12-experiment-local.json
python -X utf8 visuals/chapter-12/plot-12-01-training-matrix.py
python -X utf8 visuals/chapter-12/plot-12-02-document-split.py
```

Use local experiment output paths to preserve checked-in observations. Chapter 10's code/tests use the Python standard library; figures require matplotlib. Chapter 11's experiment additionally requires `sentence-transformers` and CPU PyTorch. The public [model card](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/blob/8b3219a92973c328a8e22fadcfa821b5dc75636a/README.md) lists Apache-2.0; model weights are not committed. The runner loads the pinned revision from a local cache by default. If absent, install the library in an isolated environment and pass `--allow-download` once to fetch that revision. The checked-in run used Python 3.14.2, sentence-transformers 5.2.2, transformers 4.57.3 and PyTorch 2.10.0+cpu; the record keeps exact versions. The hash policy normalizes CRLF to LF. Chapter 11 timing excludes model load, document encoding/index build and context selection; it includes seven randomized-order warmed search-only or query-encode-plus-exact-scan samples per method/query/depth. Local timing varies. Raw IDs/scores are useful in this fictional fixture but need access-controlled handling in a real trace.

## Measured result and next gate

The Chapter 10 top-two macro positive-query NDCG hypothesis fails: BM25 `0.8997`, exact binary cosine `0.7724`. Binary cosine misses the governing termination clause at top two; BM25 includes it. Both still omit one required signed contract-change clause at top two. All ranked/cited content stays under the support-team fixture, but two of three zero-positive questions still return irrelevant eligible candidates. At top two the checked-in local p50/p95 search-only timing is 44.5/103.0 µs for BM25 and 140.7/398.1 µs for binary cosine; this tiny Python run cannot size a production vector service. The negative result is instructive: dense storage of term presence does not add semantic information and gives up sparse candidate generation. Later ANN comparisons must keep the exact vector oracle and judged-evidence metrics separate.

Chapter 11's new probe gives a **conditional positive** result: top-two macro paraphrase Recall rises from BM25 `.8125` to frozen-encoder `1.0000`, and all-positive-query macro NDCG rises from `.7076` to `.8308`. It also exposes a wrong-product rank-one case (`p-basic`), two literal segment-ID misses by **both** methods because the IDs are not in searchable text, and candidate returns for all three no-evidence queries. Exact-identifier-slice Recall@2 remains `.6667` for both. D10 remains ineligible before scoring. The checked-in local p50 is `76.4 µs` for BM25 search versus `17,081.2 µs` for dense query encoding plus exact scan, with model load/index build separate. The 17-question set is authored and judged by one person, contains no new answer labels, and is not a general benchmark. Chapter 12's training/adaptation work must use a separate untouched test set and preserve these failures as regression cases.

Chapter 12's test result is **negative for adaptation**: on nine positive held-out-document questions, frozen and validation-selected adapted Recall@2 both equal `.889` and NDCG@2 both equal `.807`; BM25 Recall@2 is `.667`. The selected adapter changes scores but not top-two results. At epoch 5 its training loss is very low while validation Recall@2 has collapsed from `1.0` to `0`, so epoch 1 wins. All three methods return candidates for both no-evidence questions and all miss the signed Atlas contract on `te-atlas-b`. The record's local p50 query-plus-search timing is about `7.9 ms` frozen, `8.2 ms` adapted versus BM25 search `22.1 µs`; model loading, passage encoding, training and context are excluded. One author built this tiny English-only split; no broad domain, multilingual or answer-quality gain is claimed. Chapter 13 can now examine dense candidate retrieval operations against an honest frozen/adapted baseline.
